## Project tests

Project already contains some simple test samples. Based on them you may implement full test of the introduced code. 

Besides the unit and the component tests of separate classes and functions, the project holds the integration tests of the whole executables: the one of the `darknetxx`, which trains a tiny network to recognize the digits and checks its detections, and the one of the `darknetxxConverter`, which converts the weights files of every generated network back and forth. Each comes in two flavors: a GoogleTest one and a bash script one with no test framework (see the [Enabling integration testing](/doc/sections/en_US/5-3-3-enabling-integration-testing.md) section).

The network infrastructure (see the [Darknet adaptor components](/doc/sections/en_US/4-7-2-darknet-adaptor-components.md) section) comes with it's component tests:

- `CTEST_OrigWeightsFile` covers the original weights files reader, writer and validator (the `OrigWeightsReader`, the `OrigWeightsWriter` and the `OrigWeightsValidator` classes and the `save_weights`, `save_weights_upto`, `load_weights` and `load_weights_upto` functions of the Darknet C API). It generates thousands of networks and their weights files: every weights layer kind with the combinations of it's options, every header version, the resolutions from the 2x2 pixels up to the DCI 4K ones, the random networks and the real world sized ones up to the 248 MB of the YOLOv3 weights. Every file is checked byte by byte against the layout the test computes independently of the Darknet code, and the documents the files are read into write the same bytes again: the truncated files and the files of the extra bytes included.
- `CTEST_Dxxwjz1` covers the dxxwjz1 files reader, writer and validator (see the [Network weights files](/doc/sections/en_US/4-7-4-network-weights-files.md) section) over the same generated networks: the files saved of every network are checked value by value against the JSON document the test models independently (read by the zlib and the nlohmann json tree parser), the documents the test writes independently load into the networks with the loader transpositions and the skipped layers, the truncated documents, the saves and the loads up to a layer, the EMA saves, and every original weights file converts to the dxxwjz1 one and back into the same bytes and loads the same network. The float codec, the base64 text and the JSON parser are checked on their own: every special float value (the NaN payloads, the infinities, the denormals, the negative zero) round trips bit by bit and every malformed document is rejected with the path of the problem. The parse in the locales of the comma and of the multibyte decimal points is checked when such a locale is installed (`uk_UA.UTF-8`, `de_DE.UTF-8`, `fr_FR.UTF-8` or `ru_RU.UTF-8`, and `ps_AF.UTF-8`) and skipped otherwise.
- `CTEST_Dxxwjz2` covers the dxxwjz2 files reader, writer and validator: the saved networks load with their network description and training record, the reference weights files convert through the dxxwjz2 documents back into the same bytes, the JSON text of the document (the order of the members, every character of the cfg text and of the class names, the invalid UTF-8 replaced), the file of no network description refused, the network to train of no weights, the class names of another count and every malformed network or training member rejected with the path of the problem; the peek of the files stops at their weights. `CTEST_WeightsFileFormats` covers the formats of their names and file name extensions, `CTEST_TrainingJournal` the journal of the training: the losses and the mAPs recorded once in the order of the iterations, the time of the resumed training added, the files of the format given; `CTEST_TrainingChart` the chart of the training record: the chart redrawn of the record is the live one pixel by pixel, the chart of the resumed training starts with the whole record and is saved at once.
- `CTEST_WeightsModel` covers the format neutral model of the weights: the arrays of the network every generated variant makes (the `WeightsLayout` of the saves, the loads, the EMA saves and the cutoffs) are checked against the test model array by array, the schema and the document validator on their own.
- `CTEST_WeightsConverter` covers the conversion of the files between the formats: the reference and the generated weights files convert back and forth into the same bytes, every failure (the missing cfg, the network of another cfg, the corrupted file, the stop request and the rest) writes nothing into the destination and leaves no temporary file behind.
- `CTEST_ZlibController` covers the zlib compression controller: the in memory and the gzip file compression and the gzip file streams, the truncated and the corrupted gzip files included.
- `CTEST_OrigDefaultLoader` covers the network cfg parser: the reference networks and their weights, the generated networks of every layer kind checked against their specifications, the memory of the layers (the buffers of the training and the inference networks, the aliased and the shared ones), the cfg errors and the networks the loader hands to the `DarknetContext` for the training, the mAP calculation and the detection. `CTEST_CfgSection` covers the cfg file reader.
- `CTEST_ALayerAdaptor` and `CTEST_ANetworkAdaptor` cover the memory of the layers and the networks. The latter resizes the networks of every resizable layer kind and the generated ones back and forth and checks the geometry and every buffer size of their layers against the fresh parse of the new size, and the computation of every layer against the fresh network one, value by value. It computes every generated network, fuses the batch normalization without changing the network output and checks the binary weights of the XNOR layers.
- `CTEST_NetworksCApi` covers the Darknet C API implemented by the C++ adaptors, the errors which end the process included.

The generated networks and their weights files come from the `DarknetXXWeightsFactory` library of the [`src/tests/component/weights-factory`](/src/tests/component/weights-factory) directory, which the component and the integration tests share. The `DARKNETXX_WEIGHTS_TESTS_SEED` and the `DARKNETXX_WEIGHTS_TESTS_RANDOM_COUNT` environment variables change the seed and the count of the random networks (160 by default), while the `DARKNETXX_WEIGHTS_TESTS_KEEP_DIR` one names the directory to keep the generated cfg, weights and dxxwjz1 files of the tests in, for example:

```
# run from the project build directory

DARKNETXX_WEIGHTS_TESTS_RANDOM_COUNT=5000 ctest -R "CTEST_OrigWeightsFile_random" --output-on-failure
```

The dxxwjz1 families of the biggest networks (the `_resolutions`, the `_big` and the `_random` ones of the `CTEST_Dxxwjz1` and the `ITEST_converter` tests) take tens of minutes in the `Debug` build, since every float of the tens of millions goes through the JSON text, while the `Release` build runs them several times faster.

The memory tests are the most useful in the build of the sanitizers (see the [Enabling sanitizers](/doc/sections/en_US/5-13-enabling-sanitizers.md) section), which reports every access past a buffer the computation of the generated networks makes.

See the [Project build](/doc/sections/en_US/5-project-build.md) subsection to enable unit testing with CMake.
