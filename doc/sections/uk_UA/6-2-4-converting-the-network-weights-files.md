### Конвертування файлів ваг нейромереж

Окрім навчання і розпізнавання, виконуваний файл містить конвертер файлів ваг
нейромереж між шістьма форматами проекту: оригінальним файлом ваг darknet
(`*.weights`), файлом dxxwjz1 (`*.dxxwjz1`, стиснений gzip документ JSON з
вагами), файлом dxxwjz2 (`*.dxxwjz2`, документ dxxwjz1 з cfg нейромережі,
назвами класів і записом навчання поряд з вагами), проектом dxxwjz2p
(`*.dxxwjz2p`, документ dxxwjz2, що містить ще й анотації зображень YOLO4),
файлом dxxwjz3 (`*.dxxwjz3`, документ dxxwjz2 лише з даних JSON, cfg
нейромережі - це опції JSON її секцій) і проектом dxxwjz3p (`*.dxxwjz3p`,
проект dxxwjz2p з документом dxxwjz3), а також тек навчання YOLO4 у проекти
dxxwjz2p і dxxwjz3p і назад (див. секцію
[Файли ваг нейромереж](/doc/sections/uk_UA/4-7-4-network-weights-files.md)).
Конвертер викликається чотирма прапорцями командного рядка і не запускає ані
навчання, ані розпізнавання: про те, що саме конвертується, програма
повідомляє лише повідомленнями журналу, тож вона добре підходить для скриптів
і конвеєрів побудови.

```
# з директорії побудови

# оригінальний файл ваг у файл dxxwjz1
./src/darknetxx \
  --convert-from weights \
  --convert-src ./yolov3.weights \
  --convert-to dxxwjz1 \
  --convert-dst ./yolov3.dxxwjz1 \
  --convert-cfg ./yolov3.cfg

# і назад
./src/darknetxx \
  --convert-from dxxwjz1 \
  --convert-src ./yolov3.dxxwjz1 \
  --convert-to weights \
  --convert-dst ./yolov3.weights

# оригінальний файл ваг у файл dxxwjz2 з його нейромережею і класами
./src/darknetxx \
  --convert-from weights \
  --convert-src ./yolov3.weights \
  --convert-to dxxwjz2 \
  --convert-dst ./yolov3.dxxwjz2 \
  --convert-cfg ./yolov3.cfg \
  --convert-names ./coco.names

# нейромережа, яку треба навчити, з файлу cfg: файл dxxwjz2 без ваг
./src/darknetxx \
  --convert-to dxxwjz2 \
  --convert-dst ./yolov3.dxxwjz2 \
  --convert-cfg ./yolov3.cfg \
  --convert-names ./coco.names

# тека YOLO4 у проект dxxwjz2p поряд з текою зображень
./src/darknetxx \
  --convert-from yolo4 \
  --convert-src ./cars \
  --convert-to dxxwjz2p \
  --convert-dst ./cars.dxxwjz2p

# файл ваг проекту для розпізнавання, без анотацій
./src/darknetxx \
  --convert-from dxxwjz2p \
  --convert-src ./cars.dxxwjz2p \
  --convert-to dxxwjz2 \
  --convert-dst ./cars.dxxwjz2

# проект у нову теку YOLO4 з копіями зображень
./src/darknetxx \
  --convert-from dxxwjz2p \
  --convert-src ./cars.dxxwjz2p \
  --convert-to yolo4 \
  --convert-dst ./cars-yolo4
```

Проект також будує другий бінарний файл, `darknetxxConverter`, який містить
саме це конвертування і зовсім не містить навчання чи розпізнавання: ті самі
прапорці, ті самі формати, та сама поведінка. Дивись
[Бінарний файл darknetxxConverter](/doc/sections/uk_UA/5-35-the-darknetxxConverter-binary.md).

| Параметр | Значення | Опис |
| --- | --- | --- |
| `--convert-from` | `<FORMAT>` | формат файлу ваг нейромережі для читання |
| `--convert-src` | `<FILE>` | файл ваг нейромережі для читання, тека для формату `yolo4` |
| `--convert-to` | `<FORMAT>` | формат файлу ваг нейромережі для запису |
| `--convert-dst` | `<FILE>` | файл ваг нейромережі для запису, який замінюється, якщо вже існує; нова тека для формату `yolo4` |
| `--convert-cfg` | `<FILE>` | файл cfg нейромережі, якій належать ваги (або файл dxxwjz2 нейромережі) |
| `--convert-names` | `<FILE>` | файл назв класів нейромережі, які зберігає файл dxxwjz2 |

Перші чотири прапорці вказуються лише разом, або самі лише `--convert-to`,
`--convert-dst` і `--convert-cfg` створюють з файлу cfg нейромережу, яку треба
навчити. Вказати лише деякі з них - помилка, так само як і `--convert-cfg` та
`--convert-names` без них чи прапорці конвертування разом з `--train-cfg` або
`--detect-cfg`; у такому разі замість конвертування друкується довідкове
повідомлення.

`FORMAT` - одна з наведених нижче назв:

| `FORMAT` | Файл, який вона позначає |
| --- | --- |
| `weights` | оригінальний файл ваг darknet |
| `dxxwjz1` | стиснений файл ваг darknetxx у форматі JSON (darknetxx weights JSON zipped) першої версії |
| `dxxwjz2` | стиснений файл ваг darknetxx у форматі JSON другої версії |
| `dxxwjz2p` | стиснений файл проекту ваг darknetxx у форматі JSON (darknetxx weights JSON zipped project), файл dxxwjz2 з анотаціями зображень YOLO4 |
| `dxxwjz3` | стиснений файл ваг darknetxx у форматі JSON третьої версії, файл dxxwjz2 лише з даних JSON: cfg нейромережі - це опції JSON її секцій |
| `dxxwjz3p` | стиснений файл проекту ваг darknetxx у форматі JSON третьої версії, файл dxxwjz2p з документом dxxwjz3 |
| `yolo4` | тека навчання YOLO4 (лише для конвертування): нейромережа `cfg/*.cfg`, класи `data/obj.names`, списки зображень і мітки та найновіші ваги з `backup/` |

Оригінальний файл ваг не має власної структури - це лише масиви float шарів
один за одним, - тож для його читання потрібен файл cfg нейромережі, якій
належать ваги, тобто файл `--convert-cfg`. Файли dxxwjz1 і dxxwjz2 зберігають
шари і назви своїх масивів, тож конвертуються і без файлу cfg, а вказаний
файл cfg задає нейромережу, на відповідність якій перевіряється файл: шари
інших типів, масиви, яких у нейромережі немає, і масиви, довші за масиви
нейромережі, призводять до невдачі конвертування.

Файл dxxwjz2 зберігає поряд з вагами опис нейромережі, який файл призначення
формату dxxwjz2 бере з конвертування: текст файлу `--convert-cfg` (замість
cfg, який зберігає файл-джерело dxxwjz2, - один з них обов'язковий, тож файл
dxxwjz1 конвертується у файл dxxwjz2 лише з файлом cfg) і назви класів з
файлу `--convert-names` (замість класів файлу-джерела dxxwjz2, а ті - замість
файлу `names=` з cfg). Запис навчання файлу-джерела dxxwjz2 - втрати, mAP і
час його навчання - переходить у файл призначення dxxwjz2, тоді як оригінальні
файли ваг і файли dxxwjz1 зберігають лише ваги: файл dxxwjz2, конвертований
у них і назад, зберігає ті самі ваги, а запис навчання втрачається.

Файли dxxwjz3 і dxxwjz3p конвертуються так само, як файли dxxwjz2 і dxxwjz2p:
вони зберігають той самий опис нейромережі, cfg якого - це JSON її секцій,
а конвертування у файл dxxwjz2 перетворює його назад на текст cfg (без
коментарів, див. секцію
[Формат файлу dxxwjz3 третьої версії](/doc/sections/uk_UA/4-7-4-network-weights-files.md#формат-файлу-dxxwjz3-третьої-версії)).

Проект dxxwjz2p зберігає поряд із вмістом dxxwjz2 анотації зображень, які
файл призначення формату dxxwjz2p бере з джерела dxxwjz2p чи `yolo4`: проект
dxxwjz2p, конвертований у файл dxxwjz2, - це його файл ваг для розпізнавання,
без анотацій. Тека-джерело YOLO4 читається так, як її читає навчання: перша
нейромережа `cfg/*.cfg`, класи `data/obj.names`, зображення списків `train=` і
`valid=` з cfg з їхніми розмірами і рамками з їхніх файлів міток, найновіші
ваги з теки резервних копій (оригінальний файл ваг читається для нейромережі з
cfg теки). Тека призначення YOLO4 - це нова тека з нейромережею
`cfg/<name>.cfg` (з назвою теки до її першої крапки), файлами
`data/obj.names`, `data/obj.data`, `data/train.txt` і `data/val.txt`, копіями
зображень у теці `data/obj/` з їхніми мітками і вагами
`backup/<name>_last.dxxwjz3`; наявна тека з файлами не може бути місцем
призначення: конвертування в неї не вдається і залишає її без змін.

Конвертування без джерела створює нейромережу, яку треба навчити: файл dxxwjz2
лише з описом нейромережі файлу `--convert-cfg` і назвами класів, без ваг,
який навчання самого лише цього файлу навчає з нуля (див. секцію
[Файли ваг нейромереж](/doc/sections/uk_UA/4-7-4-network-weights-files.md)).
Такий файл конвертується лише у файл dxxwjz2: оригінальні файли ваг і файли
dxxwjz1 з нього не зберігали б нічого, крім заголовка, тож конвертування не
вдається.

Конвертування в оригінальний файл ваг перевіряє ще одне: такий файл не
зберігає назв своїх масивів, тож документ dxxwjz1, у якому бракує масиву
посередині або за коротшим масивом ідуть інші (наприклад, файл, відредагований
вручну), конвертувати не вдасться, оскільки масиви після пропуску
завантажилися б не в ті масиви нейромережі. Без файлу cfg немає нейромережі,
з якою можна звірити документ, і його масиви записуються як є.

Кожне конвертування зберігає кожен байт ваг: оригінальний файл ваг,
конвертований у файл dxxwjz1 чи dxxwjz2 і назад, збігається з початковим,
хай що він містить - заголовок будь-якої версії (32-бітне значення seen старих версій,
транспоновані ваги повнозв'язних шарів версій понад 1000), обрізані масиви,
зайві байти після масивів. Файл будь-якого з форматів можна конвертувати і в
той самий формат, що перевіряє його і створює з нього канонічний файл.

Про проблеми файлу-джерела програма повідомляє: помилки (файл, який неможливо
прочитати, пошкоджені чи обрізані дані gzip, документ JSON з хибною
структурою, файл іншої нейромережі) призводять до невдачі конвертування, а
попередження (обрізаний файл, зайві байти, невідомі ключі документа JSON)
записуються до журналу, і конвертування продовжується. Файл призначення
записується у тимчасовий файл у своїй директорії - директорія створюється за
потреби, - який після завершення запису замінює файл призначення, тож невдале
конвертування нічого не записує у файл призначення.

Статус завершення нульовий, якщо конвертування вдалося, і ненульовий в іншому
разі: у випадку невідомої назви формату, файлу-джерела, який неможливо
прочитати або який некоректний, чи файлу призначення, який неможливо
записати. Сигнал зупинки (натискання Ctrl+C) зупиняє конвертування між його
кроками зі статусом завершення `128 + номер сигналу` - тим самим, який
оболонка показує для процесу, завершеного сигналом.
