## Бінарний файл darknetxx-gui

Окрім програми `darknetxx`, проект будує бінарний файл `darknetxx-gui`: те
саме навчання у вікні GTK 4. Він навчає нейромережу теки YOLO4, тієї, яку
експортує [ImagesAnnotator](https://github.com/yuriysydor1991/ImagesAnnotator),
і продовжує навчання, ваги якого тека вже містить.

### Використання

```
# з директорії побудови

./src/darknetxx-gui
```

Вікно відкривається з полем теки YOLO4, заповненим поточною робочою
директорією, і кнопкою `Choose…` діалогу вибору теки. Вибрана тека, або та,
яку поле називає при натисканні клавіші `Enter`, одразу навчається:

* індикатор прогресу показує виконані і всі ітерації навчання;
* поточна похибка показується великим шрифтом, а поруч з нею середня похибка,
  швидкість навчання і години, що залишились;
* графік навчання під ними оновлюється на кожній ітерації;
* кнопка `Stop` зберігає ваги і зупиняє навчання після поточної ітерації та
  стає кнопкою `Resume`, яка продовжує навчання від збережених ваг.

Навчання продовжується щоразу, коли тека містить ваги попереднього:
найновіший файл `backup/<назва cfg>_last`, який зберігає зупинене навчання,
або найновіший інший файл `backup/<назва cfg>_*` будь-якого формату файлів ваг
(навчання зберігає файли `*.dxxwjz2`, які тримають втрати, mAP і час кожного
продовженого навчання). Графік усього запису навчання ваг dxxwjz2 показується
одразу, щойно відкрито теку, ще до першої ітерації продовженого навчання, яке
далі його домальовує (для ваг без запису продовжується зображення графіка
попереднього навчання). Вікно, закрите під час навчання, чекає, доки навчання
збереже ваги. Сигнал зупинки ОС (SIGINT чи SIGTERM, наприклад) закриває вікно
так само.

Бінарний файл приймає той самий командний рядок, що й головний (див. секцію
[Доступні параметри командного рядка](/doc/sections/uk_UA/6-2-3-available-command-line-parameters.md)),
тож параметри навчання, `--threads` чи `--net-resize-nth` наприклад,
застосовуються до навчань вікна, а тека називає файли конфігурації
нейромережі, ваг і назв класів.

### Тека YOLO4

| Шлях | Вміст |
| --- | --- |
| `cfg/*.cfg` | конфігурація нейромережі, навчається перша за назвою |
| `data/obj.names` | назви класів, по одній у рядку |
| `data/train.txt` | список зображень навчання (ключ `train=` секції `[net]` файлу cfg називає інший) |
| `backup/` | навчені ваги (ключ `backup=` секції `[net]` файлу cfg називає іншу директорію), створюється, якщо її немає |

Навчання виконується з текою як робочою директорією, тож відносні шляхи
файлу cfg і списку зображень відносні до теки, а графік кожного запуску
навчання зберігається у неї як новий файл
`chart_<назва cfg>_<РРРР-ММ-ДД--ГГ-ХХ-СС>.png` з датою і часом запуску,
найновіший з яких показує вікно.

### Побудова

Бінарний файл будується за замовчуванням і потребує файлів розробки GTKmm 4
(пакет `libgtkmm-4.0-dev` у Debian і в Ubuntu 24.04 чи новіших, див. секцію
[Обов'язкові інструменти для ОС на базі GNU/Лінукс](/doc/sections/uk_UA/3-1-required-tools-for-the-GNU-Linux-based-OS.md)).

| Параметр CMake | За замовчуванням | Дія |
| --- | --- | --- |
| `ENABLE_DARKNETXX_GUI` | `ON` | Будує бінарний файл `darknetxx-gui`, його ярлик робочого столу і піктограму. Значення `OFF` будує проект без GTKmm 4. |
| `DARKNETXX_GUI_BINARY_NAME` | `<назва головного бінарного файлу>-gui` | Назва бінарного файлу GUI і його цілі CMake. |

```
# у кореневій директорії проекту

cmake -B build -S . -DENABLE_DARKNETXX_GUI=OFF
```

Крок встановлення встановлює ярлик робочого столу і піктограму бінарного
файлу, названі за ідентифікатором програми `ua.org.kytok.template.darknetxx`,
тож меню робочих столів його показують.

### Показ вікна з пакетів і контейнерів

| Пакет чи контейнер | Що показує вікно |
| --- | --- |
| DEB | залежність від бібліотеки GTKmm 4, яку пакет обчислює за бінарними файлами |
| snap | програма `darknetxx-gui` з розширенням GNOME, яке додає середовище GTK 4 і підключення desktop, wayland, x11 та opengl |
| flatpak | середовище GNOME з модулем GTKmm 4, команда `darknetxx-gui` і дозволи Wayland, X11, IPC та DRI |
| Docker | цілі `docker-single-run-darknetxx-cpu-train-gui` і `docker-single-run-darknetxx-gpu-train-gui` |

Цілі Docker запускають скрипт [scripts/docker/gui-run.sh](/scripts/docker/gui-run.sh),
який запускає `darknetxx-gui` образу навчання на дисплеї X11 хоста (дозволеному
локальним контейнерам на час запуску) і на дисплеї Wayland сесії, якщо він є,
з текою `YOLO4_TRAINING_DATA_DIR`, змонтованою як робоча директорія (див.
секцію [Вмикання підтримки запуску Docker-контейнера](/doc/sections/uk_UA/5-12-enabling-the-docker-container-build-and-run.md)):

```
# у кореневій директорії проекту

cmake -B build -S . -DENABLE_DOCKER=ON -DENABLE_DOCKER_DARKNETXX_CPU_TRAIN=ON \
  -DYOLO4_TRAINING_DATA_DIR=/path/to/the/yolo4/folder
cmake --build build --target docker-single-run-darknetxx-cpu-train-gui
```

Образи на базі Ubuntu 22.04 не мають пакетів GTKmm 4, тож будуються без
бінарного файлу GUI.

### Як він складається з компонентів проекту

Бінарний файл - це головний бінарний файл з компонентом `src/gui`: його клас
`app::GuiApplication` (див. [src/darknetxx-gui-target.cmake](/src/darknetxx-gui-target.cmake))
показує вікно `darknetxxGtkmm4::GtkmmIniter`, а визначення `DARKNETXX_GUI`
вказує `ApplicationFactory` створити його. Вікно навчає за допомогою
`darknetxx011::ITrainer`, якого створює `darknetxx011::LibraryFacade`
бібліотеки darknetxx (див. секцію
[Бібліотека darknetxx](/doc/sections/uk_UA/4-7-5-the-darknetxx-library.md)).
Тренер запускає навчання бібліотеки у власному потоці і зупиняє його запитом
зупинки контексту бібліотеки, який підіймає і прапорець зупинки контексту
програми. Навчання повідомляє про кожну ітерацію
`darknetxx011::ITrainingListener` контексту бібліотеки, який реалізує вікно.
